# Documentación técnica

Al documentar ICMS, sigue AGENTS.md para comportamiento y autorizaciones; usa docs/contexto/project-map.md y MEMORY.md cuando sean pertinentes. Consulta fuentes técnicas desde .github/copilot-instructions.md y no mantengas copias de reglas o decisiones. La aprobación de un plan cubre solo los archivos enumerados.

Escribe documentación clara y mantenible para distintas audiencias y propósitos.

## Tipos de documento

### README

- Qué es el proyecto y por qué existe.
- Inicio rápido para llegar al primer resultado.
- Configuración, uso y contribución.

### Documentación de API

- Referencia de endpoints con ejemplos de solicitudes y respuestas.
- Autenticación, errores, paginación y límites cuando correspondan.

### Runbook

- Cuándo usarlo y qué acceso se requiere.
- Procedimiento paso a paso, rollback y escalamiento.

### Arquitectura

- Contexto, objetivos, diseño de alto nivel y diagramas.
- Decisiones, trade-offs, flujos de datos e integraciones.

### Onboarding

- Preparación del entorno, sistemas clave y tareas comunes.

## Principios

1. Escribe para la audiencia y su necesidad.
2. Empieza con la información más útil.
3. Usa ejemplos, comandos y diagramas comprobados.
4. Mantén la documentación alineada con el estado real.
5. Enlaza otras fuentes en vez de duplicarlas.
6. Distingue módulos existentes de los planeados.
7. Sigue el idioma y las convenciones Markdown de AGENTS.md.
